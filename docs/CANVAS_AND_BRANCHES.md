# Canvas and conversation branches

## Canvas

Open **Canvas** in the sidebar to try the interactive starter. Choose **Code**,
edit it, and press **Run changes** (or Ctrl/Cmd+Enter in the editor). The preview
refreshes beside the chat on larger displays and uses a full panel on phones.
The last run is saved in browser storage; closing also saves the current editor
contents and unloads the iframe to stop its scripts. **Download HTML** exports the
source as a standalone file. The starter is included application content, not an
answer generated by the loaded model.

HTML/HTM/SVG fenced blocks in model answers offer **Open in Canvas**. Code remains
plain text until explicitly opened. Inline CSS and JavaScript are supported;
external scripts, stylesheets, fonts and network requests are blocked. Data-URL
images/fonts are supported. Source is limited to 60 KB of UTF-8 text. No Node
runtime, server-side code execution, or inference call is required to use Canvas.

The server echoes source only at a dedicated preview endpoint with its own CSP:
`sandbox allow-scripts`, an opaque origin, no same-origin permission, no forms,
no child frames, and no network connections. The embedding iframe also has
`sandbox="allow-scripts"`. The main application's script policy is not relaxed.
The preview response itself carries the sandbox restriction, including when it
is viewed outside the frame. The implementation follows the documented
[iframe sandbox model](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)
and [CSP sandbox directive](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox).

Sandboxing is isolation, not a guarantee that arbitrary code behaves well: a script
can still consume CPU or render misleading content inside its own frame. Downloaded
HTML is source code; the app's HTTP sandbox policy does not accompany that file.
No browser execution or visual security audit was performed in this pass. Tests
verify the form contract, bounded input, policies, explicit-open behavior and
iframe permissions; they do not emulate browser policy enforcement.

## Branches

Use **Branch from here** below an answer to keep a copy of that conversation up to
that point. **Edit message** and **Regenerate response** now create separate paths,
preserving the source conversation. **Conversation map** displays originals and
branches; select one to resume it. A branch banner links back to its source.

Branches are independent copies, so deleting an original does not delete its
children. Missing parents appear as independent roots in the map. Existing saved
chats need no migration. Exported chat JSON includes branch metadata when present.
Storage is still local to the browser, subject to its quota; branches consume
additional space. The prior silent 150-chat save cutoff was removed. A storage
failure leaves the previously saved data intact and displays a notice.

## Related fixes and validation

Failed/cancelled requests with no output restore the user text to the composer and
remove the empty request pair, preventing duplicate user turns on retry. Existing
text typed into the composer during generation is preserved. An incomplete answer
that already contains output remains available, with regeneration creating a new
branch.

Eleven JS/DOM unit tests cover the previous chat behaviors plus branching, Canvas
opening/editing/unloading, and failed-request recovery. The Python inference-server
suite covers the new endpoint, CSP separation, source bounds and cross-origin
rejection. These features change neither model weights nor training configuration.
No training or GPU speed improvement is claimed for this pass.
